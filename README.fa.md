# SLPM — مدیر بستهٔ سادهٔ لینوکس

[English](README.md)

SLPM یک برنامهٔ وب محلی برای نصب، مشاهده، اجرا و حذف نرم‌افزارهای لینوکس است. همه‌چیز روی همان کامپیوتری انجام می‌شود که برنامه در آن اجرا شده است و برای کارهای معمول نیازی به وارد کردن دستورهای مدیر بسته ندارید.

> SLPM به‌صورت محلی و روی `127.0.0.1:8686` اجرا می‌شود.

## امکانات

- دو حالت **ساده** و **پیشرفته** که با یک کلید در نوار بالا روی تب‌هایی که به آن وابسته‌اند («برنامه‌های نصب‌شده»، «برنامه‌های استارتاپ» و «میان‌برها») تغییر می‌کنند:
  - **حالت ساده** (حالت پیش‌فرض) در تب «برنامه‌های نصب‌شده» فقط برنامه‌هایی را نشان می‌دهد که SLPM تشخیص داده است کاربر آن‌ها را نصب کرده است. در تب «برنامه‌های استارتاپ» نیز فقط موردهای کاربری دیده می‌شوند و تب «میان‌برها» مواردی را نشان می‌دهد که در منوی برنامه‌های شما ظاهر می‌شوند. این فهرست می‌تواند شامل برنامه‌های نصب‌شده با `apt`/`dpkg`، `Snap`، `Flatpak` و میان‌برهای محلی باشد.
  - **حالت پیشرفته** در تب «برنامه‌های نصب‌شده» همهٔ بسته‌های نصب‌شدهٔ `dpkg`/`apt` را نشان می‌دهد؛ از جمله برنامه‌های از پیش نصب‌شده، اجزای سیستمی و بسته‌های حیاتی سیستم. تب «برنامه‌های استارتاپ» موردهای مربوط به بسته‌های سیستمی را نشان می‌دهد و تب «میان‌برها» همهٔ موارد دسکتاپ، از جمله موارد پنهان و سیستمی را. این حالت، فهرستی یکپارچه از همهٔ منابع نرم‌افزاری نیست.
  - تب‌های «نصب» و «به‌روزرسانی‌ها» در هر دو حالت یکسان هستند.
- SLPM برنامه‌هایی را که خودتان نصب کرده‌اید از موارد از پیش نصب‌شده تشخیص می‌دهد. این کار بر پایهٔ سابقهٔ خود ابزارهای بسته انجام می‌شود: نخستین تاریخ حضور هر بسته در گزارش `dpkg`، فهرست اولیهٔ `Snap` در `seed.yaml` و زودترین زمان ویرایش پوشه‌های commit در استقرار `Flatpak`. محل فایل‌های `.desktop` یا تاریخ تغییر فایل‌های `.list` مبنای این تشخیص نیستند، چون می‌توانند نتیجهٔ اشتباهی بدهند.
- تب «برنامه‌های استارتاپ» موردهای اجرای خودکار را نشان می‌دهد. در حالت ساده می‌توانید موردهای خودتان را اضافه کنید یا غیرفعال‌کنید؛ در حالت پیشرفته موردهای ارائه‌شده توسط بسته‌های سیستمی هم دیده می‌شوند. برای غیرفعال‌کردن مورد ارائه‌شده توسط یک بستهٔ سیستمی، SLPM فایل آن را تغییر نمی‌دهد و یک فایل کاربری هم‌نام می‌سازد.
- تب «میان‌برها» برای مدیریت منوی برنامه‌ها: اجرای یک مورد، دیدن جزئیات آن، حذف میان‌برهای خودتان، و پنهان‌کردن موارد از پیش نصب‌شده از منوی شما بدون دست‌زدن به فایل‌های سیستمی. همچنین می‌توانید برای هر برنامه‌ای میان‌بر بسازید — فایل آن را با انتخاب‌گر فایل بردارید و نام، آیکون، دسته‌بندی یا اجرا در ترمینال را تعیین کنید.
- تب «به‌روزرسانی‌ها» (هر دو حالت) نشان می‌دهد هرکدام از `apt`، `Flatpak` و `Snap` چه به‌روزرسانی‌هایی دارند: می‌توانید فهرست یک مدیر بسته را باز کنید، یک مورد را جداگانه یا همهٔ موارد آن مدیر را یک‌جا به‌روزرسانی کنید و فهرست بسته‌های apt را تازه کنید. snapی که هنوز درحال‌اجراست مشخص می‌شود و SLPM پیش از به‌روزرسانی آن از شما می‌خواهد آن را ببندید؛ اگر اجرا شکست بخورد، متن کامل خطا نشان داده می‌شود، نه فقط یک خط.
- نصب با نام (فقط در حالت پیشرفته): می‌توانید هنگام نوشتن در انبارهای `apt` جست‌وجو کنید، یا یک بستهٔ `apt`، یک `snap` و یا یک برنامهٔ `Flatpak` را با نام دقیق آن نصب کنید.
- پشتیبانی از `.deb`، `.snap`، `AppImage`، فایل‌های `.flatpakref`، چند نوع آرشیو و فایل‌های `.run`/`.sh`؛ می‌توانید فایلی را که از قبل دارید نصب کنید یا آن را از یک لینک دانلود کنید. اسکریپت‌های `.run` و `.sh` خودکار اجرا نمی‌شوند و فقط می‌توانند به‌عنوان میان‌بر در منو ثبت شوند.
- هر دانلود به‌صورت یک کار در پس‌زمینه اجرا می‌شود؛ پیشرفت دانلود و کنترل‌های توقف موقت، ادامه و لغو دانلود را می‌بینید. پس از پایان دانلود، فایل به‌صورت خودکار نصب می‌شود، مگر اینکه هم‌زمان فایل دیگری را برای نصب انتخاب کرده باشید.
- اگر ابزارهای `apt`، `Flatpak` و `Snap` نصب باشند، SLPM آن‌ها را خودکار تشخیص می‌دهد.
- رابط فارسی و انگلیسی، همراه با تم روشن و تیره
- هشدار و تأیید پیش از عملیات حساس. حذف بستهٔ حیاتی سیستم می‌تواند باعث شود سیستم‌عامل بالا نیاید یا مدیریت بسته‌ها برای همیشه از کار بیفتد؛ این هشدار را جدی بگیرید. عملیات سطح سیستم برای گرفتن دسترسی مدیر از `pkexec` یا `sudo` استفاده می‌کنند و SLPM رمز شما را ذخیره نمی‌کند.

## پیش‌نیازها

- توزیعی از لینوکس با محیط دسکتاپ. AppImage منتشرشده برای معماری **x86_64** ساخته می‌شود و مفسر Python خودش را همراه دارد؛ پس چیزی از انبارهای توزیع لازم نیست. روی اوبونتو ۲۲.۰۴، دبیان ۱۲ و اوبونتو ۲۴.۰۴ آزموده شده (به یادداشت‌های انتشار نگاه کنید)؛ توزیع‌های قدیمی‌تر آزموده نشده‌اند، چون به نسخهٔ glibc موردنیاز مفسر همراه بستگی دارند.
- `pkexec` یا `sudo` برای عملیات سطح سیستم — SLPM فقط هنگام عملیاتی که به آن نیاز دارد رمز مدیر را می‌پرسد، و مدیرهای بسته‌ای که به‌کار می‌گیرد (`apt`، Flatpak، Snap) در زمان اجرا تشخیص داده می‌شوند و اختیاری‌اند.

## نصب

روش نصب پیشنهادی (و تنها روش بسته‌بندی‌شده) یک فایل AppImage است:

1. فایل `SLPM_v0.1.0-x86_64.AppImage` را از [Releases](https://github.com/parsasafaie/SLPM/releases/latest) بگیرید.
2. آن را قابل‌اجراکندید — در مدیر فایل، *Properties → Permissions* و تیک *Allow executing*، یا در ترمینال:
   ```bash
   chmod +x SLPM_v0.1.0-x86_64.AppImage
   ```
3. آن را اجرا کنید — دوبارکلیک در مدیر فایل، یا:
   ```bash
   ./SLPM_v0.1.0-x86_64.AppImage
   ```

نصب همین است: بدون ریشه، بدون وابستگی، و بدون هیچ نوشته‌ای در سراسر سیستم. اگر [AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher) یا دسکتاپی که آن را پیشنهاد می‌کند داشته باشید، نخستین اجرا می‌تواند SLPM را به منوی برنامه‌ها هم بیفزاید؛ در غیر این صورت چیزی در منو نصب نمی‌شود.

### اجرا

AppImage را اجرا کنید (دوبارکلیک یا فرمان بالا). SLPM سرور محلی خود را با کاربر عادی شما راه می‌اندازد و <http://127.0.0.1:8686> را در مرورگر باز می‌کند؛ اجرای دوباره، سرور درحال‌اجرا را تشخیص می‌دهد و فقط همان صفحه را باز می‌کند. سرور تا وقتی AppImage در حال اجراست برپا می‌ماند و بستن مرورگر آن را متوقف نمی‌کند. برای متوقف‌کردن SLPM:

```bash
kill "$(cat ~/.cache/slpm/server.pid)"
```

(بستن AppImage از داک یا نوار وظیفهٔ دسکتاپ هم همین کار را می‌کند).

عملیات‌هایی که به دسترسی مدیر نیاز دارند (نصب و حذف بسته‌ها، به‌روزرسانی سامانه) در همان لحظهٔ انجام پنجرهٔ رمز `pkexec` را نشان می‌دهند — SLPM هرگز با دسترسی ریشه اجرا نمی‌شود و رمز شما را ذخیره نمی‌کند.

### به‌روزرسانی

فایل AppImage نسخهٔ جدیدتر را بگیرید و به‌جای فایل قبلی اجرایش کنید. سرور محلی با نسخه‌ای اجرا می‌ماند که با آن راه افتاده، پس نخست SLPM را همان‌طور که بالا گفته شد متوقف کنید (راه‌اندازی دوبارهٔ سیستم هم همین اثر را دارد). تنظیمات و تاریخچهٔ شما (زیر `~/.cache/slpm`) حفظ می‌شود. فایل AppImage قدیمی هر وقت خواستید حذفش کنید — خودکفاست.

### حذف

حذف‌کننده لازم نیست: سرور را همان‌طور که بالا گفته شد متوقف کنید، فایل AppImage را حذف کنید، و اگر گزارش عملیات را هم نمی‌خواهید `~/.cache/slpm` را پاک کنید. چیزهایی که با SLPM ساخته‌اید (برنامه‌های نصب‌شده، میان‌برها، موردهای استارتاپ) سر جایشان می‌مانند.

### اجرا از سورس (برای توسعه‌دهندگان)

```bash
sudo apt update && sudo apt install -y git python3 python3-venv
git clone https://github.com/parsasafaie/SLPM.git
cd SLPM
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py  # سرو در http://127.0.0.1:8686 — فقط localhost، هرگز روی شبکه قرارش ندهید
```

## آزمون

```bash
source .venv/bin/activate
python selftest.py
```

خودآزمون یک اسکریپت ساده است و به چارچوب آزمون نیاز ندارد. منطق تحلیل و امنیت را پوشش می‌دهد: تحلیل `Exec=`، فیلترکردن فایل‌های دسکتاپ، قواعد ساخت و حذف میان‌بر، فهرست مجاز دستورات کمک‌کنندهٔ ریشه، بررسی مسیرهای آرشیو، رفتار ردکردن در پایانه‌های HTTP و فهرست ترجمه‌ها هم در سمت سرور و هم در مرورگر. چندین بررسی وضعیت واقعی همین ماشین را می‌خوانند — گزارش `dpkg`، برنامه‌های نصب‌شده و موردهای استارتاپ — تا طبقه‌بند مالکیت را سر تا پا اثبات کنند. روی ماشینی که این وضعیت جالب نیست (مثل CI یا یک کانتینر تازه)، آن‌ها را با این دستور رد کنید:

```bash
python selftest.py --skip-machine
```

## ساختار پروژه

```text
app.py              نقطهٔ ورود برنامهٔ Flask
slpm/               منطق بسته‌ها و ادغام با دسکتاپ
                    (ownership.py تصمیم می‌گیرد کدام نرم‌افزار توسط کاربر
                    نصب شده و کدام همراه سیستم بوده است، و download.py
                    لینک را در پس‌زمینه با توقف موقت، ادامه و لغو دریافت می‌کند)
templates/          قالب‌های HTML
static/             فایل‌های CSS و جاوااسکریپت
docs/               وب‌سایت GitHub Pages
appimage/           ورودی‌های ساخت AppImage (‏AppRun‏، مورد منو، آیکون،
                    فرادادهٔ AppStream)
.github/            گردش‌کار CI (خودآزمون) و گردش‌کار انتشار که برای هر
                    GitHub Release فایل AppImage را می‌سازد
selftest.py         اسکریپت خودآزمون (بدون نیاز به چارچوب آزمون)
requirements.txt    وابستگی‌های Python
```
